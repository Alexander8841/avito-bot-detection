# Классификация ботов — Avito Bootcamp (Classic ML)

Решение тестового задания по детекции автоматизированных сервисов сбора данных (ботов/парсеров) на платформе Авито по поведению внутри суточного окна наблюдения.

---

## 1. Постановка задачи и метрика

* **Цель:** На основе последовательности событий внутри 24-часового окна определить принадлежность куки (`cookie_id`) к автоматизированным сервисам сбора данных.
* **Целевая переменная:**
  * `target = 1` — трафик известных сервисов автоматизированного сбора данных (боты / парсеры).
  * `target = 0` — трафик, отнесенный к человеческому.
* **Баланс классов:** в обучающей выборке доля ботов составляет 8.11% (900 из 11 091 куки).
* **Целевая метрика:** **Precision при Recall >= 0.70** (`metric.py`), рассчитываемая на уровне уникальных кук.
  * Среди всех порогов отсечения, обеспечивающих полноту не менее 70%, выбирается порог с максимальной точностью.
  * Одинаковые предсказанные скоры обрабатываются одной группой и не разделяются.

## 3. Архитектура решения

### 3.1. Исследовательский анализ данных (EDA)
* **Временные окна:** в train 17% событий выходят за пределы суточного окна наблюдения — они отсечены (`window_start_ts <= event_ts < window_end_ts`). В test все события строго внутри окна.
* **Нормализация платформ:** выявлены технические дубликаты (`desktop` объединен с `web`, `iphone` — с `ios`). Поведение и доля ботов на `desktop` и `web` идентичны.
* **Ключевые маркеры автоматизации:**
  * **Глубина пагинации:** 90-й перцентиль просмотренной страницы поиска у ботов равен 11 (максимум до 63), у людей — 5 (медиана 2).
  * **Физика курсора:** на Web у 57.3% ботов полностью отсутствуют координаты мыши (против 28.8% у людей). Естественное перемещение мыши уверенно отделяет человека.
  * **User-Agent и ОС:** 13.2% событий ботов происходят с Linux (серверный скрапинг) против 2.0% у людей. Маркеры библиотек скрапинга (`HeadlessChrome`, `requests`, `python`, `scrapy`) присутствуют у 13.2% ботов.
  * **Временной ритм:** медианная пауза между кликами у ботов составляет 12 сек против 23 сек у людей; 75% переходов происходят быстрее 23 секунд.

### 3.2. Схема валидации
1. **Out-of-Time (OOT) Holdout:** обучение на первых 10 днях (06–15 апреля, 8 400 кук), валидация на последних 4 днях (16–19 апреля, 2 691 кука, 220 ботов, доля 8.18%). Воспроизводит хронологический сдвиг между train и test.
2. **Expanding Window Time-Series CV:** скользящая кросс-валидация на 3 фолда для проверки устойчивости моделей во времени.
3. **Adversarial Validation:** бинарная классификация train против test на сгенерированных признаках показала OOF ROC-AUC = **0.4985** (уровень случайного угадывания), что подтверждает отсутствие ковариатного сдвига (covariate shift) во времени.

### 3.3. Признаковое пространство (67 признаков)
Признаки рассчитываются векторизованно (3.08 сек на train, 1.33 сек на test) по 7 доменам:
* **Возраст профиля:** `cookie_age_days`, флаги возраста менее 7 дней и создания в день окна.
* **Временная динамика:** квантили задержек (`delta_median`, `delta_p10`, `delta_p75`, `delta_iqr`), коэффициент вариации (`delta_cv`), доли быстрых переходов (< 1 сек, < 5 сек), доля ночной активности.
* **Спектр действий и вовлеченность:** абсолютные счетчики и доли каждого из 10 типов событий, конверсии `contacts_to_views_ratio`, `fav_to_views_ratio`, `views_to_search_ratio`.
* **Марковские биграммы переходов:** частоты переходов между последовательными действиями (`item_view -> item_view`, `search -> item_view`, `item_view -> seller_page_view`).
* **Окружение клиента:** доли операционных систем (`linux`, `android`, `windows`, `macos`, `ios`), флаг `is_bot_ua`.
* **Физика курсора:** доля событий с координатами, стандартное отклонение `pointer_x_std`, `pointer_y_std`, флаг `has_zero_pointer_on_web`.
* **Охват каталога:** `search_page_max`, `search_page_mean`, `category_nunique`, `location_nunique`, `query_nunique`.

### 3.4. Интерпретация (SHAP)
Анализ SHAP TreeExplainer подтвердил физическую обоснованность решений модели:
* Высокая дисперсия координат курсора (`pointer_x_std`) и длинные межсобытийные паузы (`delta_p75`, `delta_median`) сдвигают прогноз в сторону человека.
* Высокая глубина поиска (`search_page_mean`), сканирование множества локаций (`location_nunique`) и доля Linux смещают вероятность в сторону бота.

Ноутбук генерирует файл `submission.csv` со структурой:
* Ровно 4 909 строк, соответствующих кукам из `test.csv`.
* Колонки: `cookie_id`, `score`.
* Пропуски отсутствуют, предсказанные скоры находятся строго в диапазоне `[0, 1]`.
